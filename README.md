# MoonshineWiki

Минималистичная база знаний (PWA) о домашнем самогоноварении, виноделии и пивоварении.

Mobile-first интерфейс, работает как обычный сайт и устанавливается на телефон как приложение.

## Возможности

- **Категории и статьи** с Markdown-разметкой, поиск по названию и содержимому.
- **Авторизация** на основе сессий (bcrypt + сессии в SQLite — переживают перезапуск).
- **Роли**: обычный пользователь читает, администратор создаёт/редактирует/удаляет статьи и управляет пользователями.
- **Markdown-редактор** с тулбаром, предпросмотром и безопасным рендерингом (DOMPurify).
- **PWA**: офлайн-оболочка, иконки, манифест, установка на домашний экран.
- **Docker**: готовый образ и `docker-compose.yml` с постоянным томом для базы.

## Стек

- **Бэкенд**: Node.js 22, Express 5, better-sqlite3, express-session, bcryptjs.
- **Фронтенд**: ванильный JS (SPA без сборки), marked + DOMPurify, CSS без фреймворков.
- **Хранение**: единый файл SQLite (`data/moonshine.db`) — статьи, пользователи и сессии.

## Быстрый старт (локально)

Требуется Node.js 22+.

```bash
npm install
npm start
```

Откройте http://localhost:3000

Учётные данные по умолчанию (создаются при первом запуске на пустой базе):

- логин: `admin`
- пароль: `admin123`

Их можно переопределить переменными окружения `ADMIN_USERNAME` и `ADMIN_PASSWORD`.

## Запуск в Docker

Интерактивный установщик спросит порт, логин и пароль администратора и сам поднимет контейнер:

```bash
./install.sh
```

Ручной вариант (порт и пароль берутся из `.env` или значений по умолчанию):

```bash
docker compose up --build -d
```

Приложение будет доступно на http://localhost:3000 (или на порту из `APP_PORT`). База SQLite хранится в Docker-томе `wiki-data`, а файл выгрузки данных — в папке `./data/export` репозитория.

Настройки задаются в файле `.env` (создаётся установщиком или вручную по образцу `.env.example`): `APP_PORT`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SESSION_SECRET`.

## Установка на сервере одной командой

```bash
git clone https://github.com/doc9830/MoonshineWiki.git && cd MoonshineWiki && ./install.sh
```

Установщик последовательно спросит:

1. **порт**, на котором будет доступно приложение (если порт занят — предложит другой);
2. **логин** администратора;
3. **пароль** администратора (ввод скрыт).

Ответы сохранятся в `.env`, затем соберётся и запустится контейнер.

При первом запуске на пустой базе:
- если в репозитории есть `data/export/data.json`, статьи и категории импортируются автоматически;
- создаётся администратор с указанным логином/паролем.

Затем откройте `http://<ip-сервера>:<порт>` и войдите под администратором.

> Если администратор уже был создан ранее (база не пуста), новые логин/пароль не применятся. Для полного сброса: `docker compose down -v`.

## Резервное копирование и выгрузка статей в GitHub

Статьи, категории и пользователи хранятся в SQLite-файле внутри Docker-тома. Чтобы новые статьи не потерялись, их можно выгружать в репозиторий GitHub **одной командой прямо с сервера**.

### Настройка (однократно)

1. В папке проекта на сервере добавьте удалённый репозиторий:

   ```bash
   git remote add origin https://github.com/doc9830/MoonshineWiki.git
   ```

2. Настройте доступ к GitHub одним из способов:
   - **HTTPS + Personal Access Token** (проще всего): `git config credential.helper store`, затем при первом `git push` введите логин GitHub, а в качестве пароля — токен с правами `repo`.
   - **SSH-ключ**: добавьте публичный ключ сервера в GitHub (Settings → SSH and GPG keys) и используйте remote вида `git@github.com:doc9830/MoonshineWiki.git`.

### Выгрузка данных

Одной командой с сервера:

```bash
./backup.sh
```

или через npm:

```bash
npm run backup
```

Скрипт выполняет:

1. экспорт категорий и статей из базы в `data/export/data.json`;
2. `git commit` изменённого файла;
3. `git push` в GitHub.

Если изменений нет — скрипт сообщит «выгружать нечего».

### Ручной экспорт / импорт

```bash
# Экспорт данных в JSON (в терминал)
docker compose exec app node scripts/export-data.js

# Импорт data/export/data.json обратно в базу (upsert по slug)
docker compose exec app node scripts/import-data.js
```

> В выгрузку попадают **только категории и статьи**. Пароли пользователей не выгружаются — администратор на новом сервере создаётся заново из переменных окружения.

## Переменные окружения

| Переменная       | По умолчанию                         | Описание                                   |
| ---------------- | ------------------------------------ | ------------------------------------------ |
| `APP_PORT`       | `3000`                               | Внешний порт (пробрасывается в контейнер)  |
| `PORT`           | `3000`                               | Внутренний порт HTTP-сервера               |
| `DB_PATH`        | `./data/moonshine.db`                | Путь к файлу SQLite                        |
| `SESSION_SECRET` | `moonshinewiki-dev-secret-change-me` | Секрет для подписи сессий                  |
| `ADMIN_USERNAME` | `admin`                              | Логин администратора (только первая инициализация) |
| `ADMIN_PASSWORD` | `admin123`                           | Пароль администратора (только первая инициализация) |

## API

Все эндпоинты, кроме `/api/login`, требуют авторизованной сессии. Управление статьями и пользователями доступно только роли `admin`.

| Метод | Путь                       | Описание                            | Права   |
| ----- | -------------------------- | ----------------------------------- | ------- |
| POST  | `/api/login`               | Вход (`{username, password}`)       | все     |
| POST  | `/api/logout`              | Выход                               | все     |
| GET   | `/api/me`                  | Текущий пользователь                | все     |
| GET   | `/api/categories`          | Список категорий со счётчиками      | auth    |
| GET   | `/api/articles`            | Список статей (фильтр `?category=`) | auth    |
| GET   | `/api/articles/:slug`      | Статья по slug                      | auth    |
| GET   | `/api/search?q=`           | Поиск по названию и содержимому     | auth    |
| POST  | `/api/articles`            | Создать статью                      | admin   |
| PUT   | `/api/articles/:id`        | Обновить статью                     | admin   |
| DELETE| `/api/articles/:id`        | Удалить статью                      | admin   |
| GET   | `/api/users`               | Список пользователей                | admin   |
| POST  | `/api/users`               | Создать пользователя                | admin   |
| PUT   | `/api/users/:id`           | Обновить пользователя               | admin   |
| DELETE| `/api/users/:id`           | Удалить пользователя                | admin   |

## Примечания

- Slug статей транслитерируется из кириллицы и не меняется при редактировании, чтобы внутренние ссылки между статьями оставались рабочими.
- Service worker не кэширует API — данные всегда запрашиваются с сервера; офлайн работает только для оболочки приложения.
- Демо-контент (9 категорий, ~26 статей) создаётся только один раз при пустой базе.
- Если в репозитории есть `data/export/data.json`, при первом запуске он импортируется вместо демо-контента.
